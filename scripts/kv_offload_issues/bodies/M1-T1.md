**Summary:** Add a read-only Python accessor returning an opaque handle over the device address that backs a `device("spyre")` tensor's storage (already held on the tensor's owner context — no new bookkeeping). This is the one tensor-aware step the design assigns to torch-spyre.

### What

- `get_composite_address(dev_tensor) -> CompositeAddressHandle` bound next to the existing copy/stream bindings.
- Handle holds no ownership; invalidated when the tensor's storage is freed.

### Unit tests

- Returns a handle whose reported chunk shape matches the tensor's allocation.
- Rejected (raises) after the tensor's storage is freed.
- No change to existing copy paths (regression).

### Acceptance

- [ ] Handle chunk shape matches allocation.
- [ ] Use-after-free rejected.
- [ ] Existing copy paths unaffected.

**Blocked by:** none
